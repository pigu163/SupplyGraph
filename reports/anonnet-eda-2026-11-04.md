# AnonNet 简单 EDA 与建图建议

日期：2026-11-04

范围：只读检查本地 `nodes_anon.csv`、`edges_anon.csv`，并在内存中分析网络结构。未向 Neo4j 导入数据。

## 结论先看

这份数据适合先做**匿名公司之间的网络结构分析**：文件完整性较好，节点 ID 与关系端点能够对齐；网络中也有明显的高度连接节点和潜在结构瓶颈。

但有三件事需要在建模前明确：

1. 官方资料说边代表公司间供应关系，但在本次查阅的资料中，没有找到 `source` 和 `target` 分别代表供应商还是客户的说明。先按文件中的方向保存，暂不将它翻译成业务上下游。
2. 地点缺失 20.57%，产品缺失 7.41%；地点和产品字段的含义、拆分方式不能只凭分隔符推断。
3. 这是匿名、可能含噪声的静态快照；缺少容量、需求、库存、交易量、日期和合同信息。路径可用于描述潜在暴露，无法直接证明停产、实际损失或替代供应商可用。
4. 当前 Compose 将原始 `dataset/` 以读写方式挂载到 Neo4j 导入目录；未来运行导入前应评估单独的导入副本或合适的容器权限，避免启动脚本或操作影响原始文件。此前直接只读挂载曾因启动时调整目录权限失败，方案需在隔离环境验证。

数据提供方说明节点为公司、边为供应关系，地点与产品是节点属性；竞赛说明还指出公司可能在多个国家运营，数据是静态快照，可能存在不确定性或噪声。[AnonNet 数据页](https://supplychaindatahub.org/datasets/anonnet/) · [竞赛数据说明](https://supplychaindatahub.org/mim25_data_challenge/network-25/)

## 数据里有趣的地方

### 1. 网络高度连通，但方向的商业含义未证实

- 按 CSV 的 `source → target` 作为**文件方向**建立简单有向图，保留自连接；7,245 个节点全部在同一个弱连通分量中，即忽略方向后都能通过某种路径连接。
- 最大强连通分量包含 3,871 个节点（53.43%）：在文件方向下，这些节点之间彼此可达。这是网络拓扑，不代表这些公司之间一定有实际资金流、循环交易或中断传播。
- 每个节点都至少出现一次在 `target` 列；3,237 个节点（44.68%）没有出现为 `source`。这值得进一步调查数据生成或抽样方式，但现有材料不足以解释原因，也不能据此断言这些节点都是终端客户或供应商。
- 排除自连接后，约 13.02% 的有向边存在相反方向的边。它们可能有不同含义，不能自动视为重复记录。

### 2. 单一高连接节点可以作为结构情景示例

`n4859` 是 `source` 端连接数最高的节点，有 **483** 条出边；全体节点的 `source` 端连接数中位数为 **1**，第 90 百分位为 **15**。这里的“出边”仅表示 CSV 的文件方向。

作为一个可复现的**无向结构演示**：把边当作无向边，在内存中移除 `n4859` 后，剩余 7,244 个节点分成 25 个连通分量；最大分量有 7,220 个节点，另外 24 个节点成为单节点分量。完整无向图有 419 个割点。

这个结果说明 `n4859` 在当前快照中连接了一些结构上依赖它才能与主体网络连通的节点。它不说明 24 家公司会停止经营，也没有使用容量、库存、替代供应商或时间信息；此示例不是有向级联模拟。

### 3. 地点有一定集中，但不是完整的经营足迹

对地点**仅去除首尾空格**后，出现最多的原始地点标签是 Japan 1,099、China 1,086、United States 720、South Korea 481、Taiwan 300；上述数字的总体分母是 7,245 家公司，其中 1,490 条地点为空。

地点字段里有 `Virgin Islands, British` 这样的值，直接按逗号拆地点会破坏名称。官方资料又说明一家公司可能在多个国家运营，因此单个文本字段也不能被视为完整的工厂或经营地点清单。

### 4. 产品字段不能直接当作标准产品目录

3,550 行产品字段包含逗号；例如 `n9` 的原值是 `Lead, Lead, Refined lead`，存在重复文本。另有包含 `Forestry, Paper & Wood Products` 的字段，逗号既可能用于分隔条目，也可能属于名称本身。本次没有找到可验证的正式拆分规则或产品字典。

字段里既有材料名称，也有 `Asset Management`、`Insurance` 等服务或行业标签。因此，相同文本最多是候选匹配信号；不能直接当作标准零件、供需匹配关系或已证实的替代能力。

## 推荐的首版图模型

先采用最小、保留原始信息的模型，待来源语义和清洗规则核实后再扩展：

```text
(:Company:AnonNetCompany {
  anonnetId, locationRaw, productsRaw, sourceDataset, sourceSnapshot
})
  -[:REPORTED_SUPPLY_LINK {
      sourceDataset, edgeFileSha256, directionMeaning: 'unverified'
    }]->
(:Company:AnonNetCompany)
```

- `anonnetId` 保存如 `n4859` 的原 ID；在 `AnonNetCompany` 标签范围约束唯一，避免与未来其他数据源的 ID 混淆。
- 关系的起点和终点分别对应 CSV 的 `source` 和 `target`；`REPORTED_SUPPLY_LINK` 只表达来源报告了一条供应关系及其原始文件方向。**它暂不声称起点是供应商。** 方向证实后再讨论是否迁移为 `SUPPLIES_TO`。
- `locationRaw`、`productsRaw` 保留 CSV 原文。可以另存去除首尾空格的地点供统计，但不能覆盖原值；空白表示缺失。暂不将逗号切分结果直接建立为 `Product` 节点。
- `sourceSnapshot` 记录所导入文件的版本或哈希；本地下载时间和未来导入时间不是关系发生或生效的时间。数据中没有逐条来源、日期或置信度时，不凭空补造。
- 四条自连接和双向边在原始图中保留，并在质量报告及分析视图里显式区分；是否在某个算法投影中排除由算法定义决定。

## 拟议 Neo4j 导入步骤（尚未执行）

1. **检查目标数据库现状。** 查看现有标签、关系、约束、索引和目标数据，避免覆盖其他项目；确认文件挂载、数据库版本与 GDS 插件可用。
2. **审计并固定输入版本。** 校验 CSV 哈希、字段、ID 唯一性、缺失端点、重复边和自连接；记录异常与处理结果。原始 CSV 保持不变。
3. **建立约束，再导入节点。** 为 `AnonNetCompany.anonnetId` 建唯一性约束；用 Neo4j 5.22 支持的 `LOAD CSV` 或 Python 驱动分批参数化写入，保留原始属性及来源。此数据规模约 5 万行，优先采用简单的串行在线导入。
4. **匹配两端，再导入关系。** 按原始 `source → target` 找到两个已导入节点，使用幂等的串行合并方式创建 `REPORTED_SUPPLY_LINK`；保留 4 条自连接和 2,859 对反向关系，显式报告缺失端点和失败批次，不静默跳过。
5. **对账与重跑。** 若选择全部保留原始关系，预期是 7,245 个 AnonNet 节点、43,926 条该来源关系、4 条自连接；通过前后计数、抽样端点、原始属性与缺失值核对。重复导入不得增加节点或关系。
6. **之后再建立 GDS 投影。** 检查实际 Neo4j/GDS 版本和可用过程；分别明确有向与无向投影、是否排除自连接、内存估算和清理方式。WCC、度数和 PageRank 是结构指标；图方向未确认前不可将排名叫作供应商关键性。

Neo4j 5 的 `LOAD CSV` 支持从导入目录读取本地文件；在较大导入中使用分批事务时，已提交批次可能保留，因此失败恢复和对账必须显式处理。5.22 使用相应版本语法，不能直接照搬 5.23+ 的变量作用域语法或 Cypher 25 示例。[Neo4j 5 LOAD CSV 文档](https://neo4j.com/docs/cypher-manual/5/clauses/load-csv/)

## 复现与边界

在项目根目录运行：

```bash
uv run python scripts/data/eda_anonnet.py
```

脚本使用 Python CSV 解析器和 NetworkX，输出 JSON，不写入数据库或修改 CSV。节点 ID 和边端点只在比较前去除首尾空格；地点统计只去除首尾空格；未拆分产品或地点。重复边按有序 `(source, target)` 统计；图采用 `DiGraph`，保留自连接；互惠比例排除自连接。度数分位数使用排序后 `floor((n-1) × 分位数)` 的位置。

数量、空值、唯一 ID、重复有向边、自连接和端点匹配另用 Polars 独立核对，结果一致。图结果属于当前数据快照的描述，不代表对全部供应链的推断。

来源仓库未发现独立 LICENSE 文件，数据页称其可免费下载并提供 as-is 声明；公开再分发前应确认许可。历史竞赛页面提到比赛最终数据需注册，而后来发布的 AnonNet 数据页链接到公开仓库；两处说明对应不同发布场景，不能据此自行补写许可。
